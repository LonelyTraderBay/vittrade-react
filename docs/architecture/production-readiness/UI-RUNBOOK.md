# Runbook xem trước và nghiệm thu UI VitTrade

Tài liệu này giúp chạy giao diện development độc lập backend, xem các persona mock và ghi kết quả theo từng page/route. Fixture chỉ phục vụ thử UI, không đại diện giá thị trường thật và không thực hiện giao dịch. “Mock preview chạy được” không đồng nghĩa trang đã được nghiệm thu hoặc backend đã tích hợp.

Theo dõi page, route, API operation và từng bước trong [TRACKING.json](TRACKING.json); ưu tiên công việc theo [PLAN.md](PLAN.md). Khu vực cần chú ý: [cấu hình môi trường](../../../src/shared/config/env.ts), [bootstrap](../../../src/main.tsx), [điều khiển preview](../../../src/dev/PreviewControls.tsx), [persona mock](../../../src/dev/mocks/personas.ts), [login UI](../../../src/features/auth/pages/WebLoginPage.tsx), [ví dụ biến môi trường](../../../.env.example), [ví dụ staging](../../../.env.staging.example) và [ví dụ production](../../../.env.production.example).

## 1. Khởi động mock trên Windows

Mở PowerShell tại thư mục gốc repository. Cần có Node.js/npm và dependency trong node_modules. Trong workspace này, npm.cmd run dev -- --version không phân giải được lệnh vite; lệnh Vite trực tiếp dưới đây đã khởi động được server. Nếu npm.cmd run dev hoạt động trên máy của bạn, có thể dùng script đó thay thế.

    $env:VITE_DATA_SOURCE = 'mock'
    node .\node_modules\vite\bin\vite.js --host 127.0.0.1 --port 4173 --strictPort

Giữ cửa sổ PowerShell đang chạy. Mở trình duyệt tại:

- Trang đăng nhập web: <http://127.0.0.1:4173/w/auth/login>
- Thị trường mẫu đã chạy kiểm tra: <http://127.0.0.1:4173/w/markets>

Thoát bằng **Ctrl+C**. Nếu cổng **4173** đã có chương trình khác, đổi tham số port thành **4174** rồi mở đúng cổng mới trong trình duyệt. Tắt server trước khi đổi VITE_DATA_SOURCE; cấu hình được đọc lúc Vite khởi động.

Khi mock hoạt động, góc dưới bên phải có cảnh báo “DỮ LIỆU MÔ PHỎNG · KHÔNG PHẢI GIAO DỊCH THẬT”. Nếu cảnh báo không hiện, đừng coi dữ liệu đang thấy là fixture đã xác minh; kiểm tra URL, biến VITE_DATA_SOURCE và cấu hình server.

## 3. Chọn trang và kiểm tra giao diện

Điều khiển preview có lối tắt Trang chủ, Thị trường, DCA và P2P. Các lối tắt chỉ điều hướng; chúng không tạo hoặc chọn trạng thái dữ liệu riêng. Thị trường đã được kiểm tra trên browser development và hiển thị 2/2 fixture:

| Cặp | Giá mẫu | Thay đổi mẫu |
| --- | ---: | ---: |
| BTC/USDT | 67,543.21 | +2.34% |
| ETH/USDT | 3,521.45 | -1.23% |

Để thử trạng thái API mock, mở **Trạng thái API mock**, chọn miền, chọn trạng thái rồi bấm **Áp dụng trạng thái API**. Công cụ lưu lựa chọn trong `localStorage` và làm mới query đang hoạt động thuộc miền đã chọn, giữ nguyên persona đăng nhập trong bộ nhớ. `success` dùng handler/fixture hiện tại; `loading` trì hoãn phản hồi 2 giây rồi cho request chạy qua handler thật; `error` tùy miền/hợp đồng: chỉ dùng status 5xx đã khai báo; nếu không thì lỗi transport. Mutation giữ handler thường để không giả định kết quả ghi. `unauthorized`/`forbidden` chỉ áp dụng operation được hỗ trợ. Riêng `market.error` trả 503 rỗng cho 7 provider GET khai báo status này, lỗi transport không status cho 9 GET còn lại, và để cả 6 mutation đi qua handler thường. ## 5. Chạy API mode khi có backend thử nghiệm

Dừng dev server, rồi đặt URL backend thử nghiệm trước khi chạy. Thay hai host mẫu bằng endpoint được nhóm backend cung cấp; API base không có dấu / cuối. WebSocket chỉ cần khi luồng trang được thử sử dụng realtime.

    $env:VITE_DATA_SOURCE = 'api'
    $env:VITE_API_BASE_URL = 'https://<api-host-thu-nghiem>'
    $env:VITE_WS_URL = 'wss://<websocket-host-thu-nghiem>'
    node .\node_modules\vite\bin\vite.js --host 127.0.0.1 --port 4173 --strictPort

Mở cùng URL ứng dụng trên trình duyệt. Trong API mode không có cảnh báo hoặc điều khiển mock; request của ứng dụng đi qua API client tới backend đã cấu hình. Nếu backend chưa chạy hoặc URL còn placeholder, request có thể lỗi mạng. Ứng dụng không tự chuyển về fixture. Ví dụ .env.example hiện dùng https://api.example.invalid và wss://ws.example.invalid, là host mẫu không dùng được cho tích hợp thật.

Browser smoke hiện tại mở được trang đăng nhập API mode mà không có preview panel, nút Demo hoặc credential hints. Khi thử submit dữ liệu giả cục bộ trong API mode với endpoint `http://127.0.0.1:4199` không có service lắng nghe, giao diện vẫn ở trang login và hiện lỗi đăng nhập; nó không rơi về fixture. Bằng chứng này chỉ xác nhận cách UI phản ứng khi API ngoại tuyến, không xác nhận API contract hay đăng nhập backend thật. Xem [API-mode offline smoke](evidence/A05/api-mode-offline-smoke.json).

Các giá trị VITE_* được đưa vào mã client; không đặt API secret, private key, mật khẩu backend hoặc credential dùng chung trong chúng. Không đưa production credential vào máy nghiệm thu UI.

Khi đổi từ mock sang API trên cùng origin, bootstrap tìm worker `/mockServiceWorker.js`, gỡ registration đó rồi tải lại một lần trước khi render. Unit tests kiểm tra worker đúng origin/script, giữ nguyên worker không liên quan và dừng bootstrap khi cleanup lỗi. Kiểm tra runtime bằng Chromium trên cùng browser context đã quan sát worker ở trạng thái `activated` trước khi chuyển mode và `registrations: []` sau bootstrap API; chi tiết cùng ảnh UI ở [bằng chứng retire worker cùng origin](evidence/A05/same-origin-worker-retirement-2026-09-28.json). Phiên kiểm tra dùng cổng cô lập 4174; preview có sẵn ở 4173 vẫn chạy. Backend API localhost không lắng nghe; không gửi credential hay thao tác giao dịch. Kết quả này đóng kiểm tra browser của A05.05, không xác nhận backend thật hoặc việc loại static worker khỏi production artifact (C04.02). Xem thêm [biên bản giới hạn browser trước đây](evidence/A05/preview-api-browser-limitation.md) để phân biệt lần thử không kết luận với bằng chứng runtime sau đó.

### Quy trình kiểm tra worker thủ công trên cùng origin

Có thể dùng quy trình này để kiểm tra lại bằng DevTools. Nó tạm dừng preview mock trên origin được chọn trong lúc đổi mode; không chạy nếu đang cần giữ preview liên tục. Dùng chính URL và host/port của tab mock ban đầu (ví dụ `http://127.0.0.1:4173`), không đổi `127.0.0.1` thành `localhost` vì đó là origin khác. Bước này đã có bằng chứng pass ở [EV-20260928-001](evidence/A05/same-origin-worker-retirement-2026-09-28.json); không cần chạy lại chỉ để xác nhận cùng một kết quả.

1. Trên trang mock ban đầu, mở DevTools → Application → Service Workers và ghi lại origin cùng script URL đang đăng ký. Không bấm Unregister, Clear site data hoặc xóa registration thủ công.
2. Dừng Vite mock, rồi trong cùng PowerShell đặt API mode và khởi động Vite trên đúng host/port đó. API base thử nghiệm phải không có server lắng nghe; không dùng tài khoản thật hoặc thao tác giao dịch.

       $env:VITE_DATA_SOURCE = 'api'
       $env:VITE_API_BASE_URL = 'http://127.0.0.1:4199'
       node .\node_modules\vite\bin\vite.js --host 127.0.0.1 --port 4173 --strictPort
3. Mở lại cùng URL trong cùng browser profile, đợi bootstrap tự xử lý và reload. Trong Application → Service Workers, kiểm tra registration thuộc origin đó; xác nhận không còn script `/mockServiceWorker.js`. Không tự gỡ worker để làm cho kết quả đạt.
4. Ghi thời gian, URL origin, script URL trước/sau và kết quả thực tế vào phản hồi nghiệm thu. Nếu script vẫn còn hoặc trang lỗi trước khi bootstrap hoàn tất, giữ A05.05 mở và ghi nhận đúng trạng thái.
5. Sau khi ghi nhận, có thể dừng API mode và khởi động lại preview bằng `VITE_DATA_SOURCE='mock'` trên origin ban đầu.

Nếu tái kiểm tra, chỉ ghi pass khi quan sát bước 3 trên đúng origin và trong cùng browser profile; hướng dẫn này tự nó không phải bằng chứng worker đã được gỡ.
